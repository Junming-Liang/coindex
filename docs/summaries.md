# 总结

macOS 和 Linux 左侧都有「总结」。进入后先选择范围，再生成总结；已生成内容保留在总结历史中。

## 选择范围

- **正在进行中的全部待办**：选择当前未完成、未忽略的事项，包括稍后处理的待办。
- **全部已保存任务（含完成、归档）**：选择本地已经保存的全部任务，包含已完成、已解决、已结束及归档对话的任务，合并重复项除外。自动总结也可选择此范围。
- **指定时间段的全部待办**：选择仅一天、近三天、近一周或自定义起止日期。以北京时间自然日计算，包含起止两天；范围内新建、更新或完成的待办都纳入，包括手动待办与已归档对话的待办。

时间范围根据本地保存的任务活动记录判断。升级前只回填现有数据能够证明的时间点，不能还原未保存的历史变化。总结使用生成时冻结的任务进度；它不是所选日期结束时的完整历史快照。

范围预览显示已纳入的归档对话任务数量，来源清单标记归档状态。读取这些历史记录不会恢复归档会话的追踪；从未保存到 coindex 的历史会话不会凭空生成任务。

## 工作筛选与格式

需要工作汇报时，可启用「仅总结工作任务」，并填写可选的工作背景提示，例如工作项目或职责。个人开源项目和自己制作的应用会从工作总结中排除；无法判断归属的事项保留并标注待核对。排除记录可查看，筛选不会删除、完成或修改待办。手动生成与自动总结使用相同规则。

每个目标统一包含四项，各项一句话：

| 字段 | 内容 | 最大长度 |
| --- | --- | --- |
| 问题背景 | 为什么要做这件事 | 50 字符 |
| 具体问题 | 要解决的核心问题 | 50 字符 |
| 目前实验结果 | 已记录的实验、验证或交付结果 | 80 字符 |
| 实验结论 | 记录支持的判断或结论 | 50 字符 |

没有实验结果或结论的任务明确显示未记录，不补造结果。总结引用当前待办记录，不能替代外部实验、CI 或交付物的实际验收。

总结调用设置中配置的 Codex 模型和推理强度，默认 `gpt-6-luna` / `max`。任务文字作为资料处理，不执行其中的指令。生成失败时保留已有总结和原待办。

每条任务的可引用依据独立约束，模型不能引用其他任务或未提供的编号。格式或引用校验失败时，当前批次最多生成三次并提供纠错反馈；不会把无效引用替换为默认编号，也不会将未核实的结果保存为完成状态。

## 自动总结

自动总结默认关闭。在「总结」中启用后，可设置范围、工作筛选条件以及每日、每周或按小时的频率。每日 / 每周可选执行时间，每周另选星期；按小时间隔支持 1–168 小时。默认设置为每日 18:00，总结一天。日程按北京时间计算，重启后保留设置和历史。

自动总结需要应用保持运行，遵守下班暂停，也可设置只在工作日执行。应用退出或设备休眠时不能准时生成；恢复后把错过的时点合并为一次当前总结，不逐条补发。生成失败也会消耗本次时点，可查看错误后手动重试。调度与待办自动更新分别设置。

模型生成会使用你的 Codex 配额。先手动生成并检查范围和格式，再启用合适的自动频率。
