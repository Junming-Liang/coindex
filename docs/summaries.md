# 总结

macOS 和 Linux 左侧都有「总结」。进入后先选择范围，再生成总结；已生成内容保留在总结历史中。

## 选择范围

- **正在进行中的全部待办**：选择当前未完成、未忽略的事项，包括稍后处理的待办。
- **全部已保存任务（含完成、归档）**：选择本地已经保存的全部任务，包含已完成、已解决、已结束及归档对话的任务，合并重复项除外。自动总结也可选择此范围。
- **指定时间段的全部待办**：选择仅一天、近三天、近一周或自定义起止日期。以北京时间自然日计算，包含起止两天；范围内新建、更新或完成的待办都纳入，包括手动待办与已归档对话的待办。

时间范围根据本地保存的任务活动记录判断。升级前只回填现有数据能够证明的时间点，不能还原未保存的历史变化。总结使用生成时冻结的任务进度；它不是所选日期结束时的完整历史快照。

范围预览显示已纳入的归档对话任务数量，来源清单标记归档状态。读取这些历史记录不会恢复归档会话的追踪；从未保存到 coindex 的历史会话不会凭空生成任务。

## 工作筛选与格式

需要工作汇报时，可启用「仅总结工作任务」，并填写可选的工作背景提示，例如工作项目或职责。个人开源项目和自己制作的应用会从工作总结中排除；无法判断归属的事项保留并标注待核对。排除记录可查看，筛选不会删除、完成或修改待办。手动生成与自动总结使用相同规则。

总结采用团队站会 / 周报中的专项汇报写法：以原任务的整体目标为标题，直接交代做了什么、实际结果和下一步。必要背景融入进展；同一目标的多轮尝试按当前结论整理，避免复述聊天和工具过程。

| 字段 | 内容 | 最大长度 |
| --- | --- | --- |
| 进展 | 具体问题、采取的改动或实验、当前阶段 | 240 字符 |
| 结果与结论 | 已观察的结果、对照及记录支持的判断 | 360 字符 |
| 下一步 | 记录中已有的后续实验、验证或交付动作；无记录时省略 | 160 字符 |
| 风险与阻塞 | 明确的依赖、回退或关键验证边界；没有独立内容时省略 | 160 字符 |

有指标时保留方案 / 基线、样本量、版本与评测范围，说明收益与回退。无收益、失败和不确定原因也如实写出，不把提交、排队、训练中或单测通过写成效果改善。没有实验结果时明确写出当前阶段和暂无可验证结果，不补造收益或后续计划。

例如下面是**虚构资料**对应的写法，数字只作展示：

```markdown
## 1. 降低批处理耗时

- **进展**：将逐条处理改为批量处理，完成同批数据的对照测试。
- **结果与结论**：20组样本耗时由12分钟降到9分钟；大批次仍有内存回退，暂未验证完整生产负载。
- **下一步**：按已记录计划复核大批次内存峰值。

### 相关产物

- [性能分析文档：测试口径与逐组结果](https://docs.example.org/wiki/batch-report)

![同批耗时对比图](/workspace/output/batch-comparison.png)
```

## 文档、图片与其他产物

每个专项下整理最多 8 项直接相关的材料，优先保留实验 / 分析文档、指标报告、对比图、代码变更和交付包。文档和配图互补时一并保留，并用简短说明交代材料对应哪项结果。同一入口去重，无关链接和计划中尚未生成的材料不纳入。

候选材料从生成时冻结的任务字段和可见对话中提取，包括 Markdown 文档 / 图片链接、网页 URL 以及文件路径。相对文件路径只有在对话已保存工作目录时才解析。本机图片在 macOS 总结中可预览；无法加载时保留原图入口。Linux 显示 Markdown 文本；复制或导出的 Markdown 保留文档链接与图片嵌入语法。远端文件标明机器与路径，不能当作本机文件打开。

模型只能选择本任务实际存在的候选编号并写说明，不能自己提供 URL 或路径。每个选中产物必须引用其出处记录；越界、跨任务、重复或缺少依据的选择都会触发纠错。带凭据或签名参数的链接不进入产物清单。

材料入口来自保存记录，生成总结时不会联网、读取文件、下载材料或新建文档 / 图片，也不会重新验证链接可用性。已截断或未被采集的历史材料可能缺失；没有图片入口时不生成占位图，也不推测图中指标。查看总结时，macOS 会尝试加载已附图片；需要登录的图片可通过原图入口打开。

总结引用当前待办和可见对话记录，不能替代外部实验、CI 或交付物的实际验收。原有历史总结保持原文，新格式用于之后生成的总结。

总结调用设置中配置的 Codex 模型和推理强度，默认 `gpt-6-luna` / `max`。任务文字作为资料处理，不执行其中的指令。生成失败时保留已有总结和原待办。

每条任务的可引用依据独立约束，模型不能引用其他任务或未提供的编号。格式或引用校验失败时，当前批次最多生成三次并提供纠错反馈；不会把无效引用替换为默认编号，也不会将未核实的结果保存为完成状态。

## 自动总结

自动总结默认关闭。在「总结」中启用后，可设置范围、工作筛选条件以及每日、每周或按小时的频率。每日 / 每周可选执行时间，每周另选星期；按小时间隔支持 1–168 小时。默认设置为每日 18:00，总结一天。日程按北京时间计算，重启后保留设置和历史。

自动总结需要应用保持运行，遵守下班暂停，也可设置只在工作日执行。应用退出或设备休眠时不能准时生成；恢复后把错过的时点合并为一次当前总结，不逐条补发。生成失败也会消耗本次时点，可查看错误后手动重试。调度与待办自动更新分别设置。

模型生成会使用你的 Codex 配额。先手动生成并检查范围和格式，再启用合适的自动频率。
